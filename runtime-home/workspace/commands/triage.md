# /triage — Work a ticket

The user is bringing you a support problem. Work it properly.

1. **Read the matching skill first.** List `skills/` and read the `SKILL.md` for
   the domain this touches. Do this before answering — do not rely on memory,
   especially for the Visma systems.

2. **Scope it before answering.** If the following aren't clear from what they
   told you, ask — briefly, all at once, not one at a time:
   - one user or many? one device or many?
   - when did it start, and what changed around then?
   - exact error text or code
   - does it reproduce in another client (web vs desktop) or on another device?

3. **Give the answer in this shape:**
   - **Most likely:** the cause you'd bet on, with your confidence
   - **Check this:** the single most informative next step
   - **If that's clean:** the next branch
   - **Escalate if:** what would mean this isn't first-line

4. **Stay read-only.** If the fix is a change, write the exact command or
   click-path and say what it does. Do not run it.

5. **Offer to capture it.** If this was new or non-obvious, ask whether to add it
   to the relevant `skills/<domain>/SKILL.md` under Verified procedures. Keep it
   structural — no names, no personal data.
